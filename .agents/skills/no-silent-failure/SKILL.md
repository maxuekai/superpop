# 不许无声失败

玩家能察觉到的只有两件事：**一个控件没反应**，和**一个东西不见了**。
这两件事如果没有明确归因，玩家的解读永远是"坏了"。

## 一、禁用态必须说得出原因

同一个控件被多种原因禁用时，玩家看到的是同一个视觉。

```
❌ canSplit 返回 false → 按钮 .hidden  → "按钮怎么不见了"
✅ canSplit 返回 false + reason → 按钮显示"已达上限"
```

**做法**：判定函数返回"为什么不能"，不只返回"能不能"。

- 本项目的实例：`rules.splitStatus()` 返回 `{canSplit, cooldownLeft, cooling, atCellLimit}`，
  `Hud.updateSplit()` 据此显示「分裂 / Ns / 已达上限」
- 只有**能从画面上看出来的**原因才需要文字说明。"球还太小"是看得见的，不用写；
  "达到分身上限"看不出来，必须写

**只有真正需要玩家操作的控件才用 `disabled`。** 纯展示的元素不要放 `<button>`，
放 button 就会自带"我能按"的暗示。

## 二、任何"东西消失"都要有去向

场上对象减少，可能是完全不同的几条路径。玩家分不清，所以**每条路径都得有日志或反馈**。

至少枚举这几条：

| 路径 | 玩家看到的是什么 | 该怎么办 |
|---|---|---|
| 被吃掉 | 球不见了 + 质量给谁了 | 正常，有动画最好 |
| 被系统移除（数量平衡） | 球凭空不见 | **要么别做，要么明说** |
| 重生到视野外 | 过几秒在别处冒出来 | 重生时给反馈，或让重生点可见 |
| 状态重置 | 整场变了 | 明确提示（"新的一局"） |
| 异常（不该发生） | 球无故消失 | 必须能从日志里查出来 |

本项目的实例：`syncAiCount` 超编时会**永久移除**最大的几个 AI（`respawnAt = Infinity`，
不进重生队列）——玩家眼里这就是凭空消失。现在它有 `log('数量', ..., 'warn')`，
而且重生走 `restartWorld()` 把世界一起重置。

**验收方法**：把所有让对象数量减少的代码路径列一遍，逐个问"玩家怎么知道"。

## 三、状态变化要留痕

不是所有状态变化都要给玩家看动画，但**必须能事后查**。

`src/core/log.js` 提供分级日志（debug / info / warn / error）+ 环形缓冲 +
每秒快照（玩家质量 / 名次 / AI 数 / 最大 AI / 帧耗时）。默认关闭，`?debug=1` 打开。

- 高频、无歧义的变化 → `debug`（会被级别过滤掉）
- 玩家可能觉得意外的变化 → `warn`
- 不该发生 → `error`

## 四、阈值只有一个语义一份

这个仓库最大的 bug 类别：`同一个概念在两个地方用了两个阈值`。
互食用 `r1`、软碰撞用 `r1+r2`，于是猎物被锁死在两个阈值之间的空隙里，
**谁都吃不掉谁**，而语法检查和单测全绿。

改动任何判定前先问：这个阈值和别处判断同一个概念的地方，一致吗？

## 走查清单

改完 UI 或数量逻辑后过一遍：

- [ ] 每一个能点/不能点的控件，都能在界面上说出"为什么"
- [ ] 纯展示元素没有用 `button`
- [ ] 场上对象数量减少的每条路径都有日志
- [ ] "异常消失"有 `error` 级日志，能被事后查出来
- [ ] 同一语义的阈值在各模块之间一致
- [ ] `?debug=1` 跑一遍，面板能看出这些变化
